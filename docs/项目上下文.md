# 《雪夜旅馆》项目上下文

更新时间：2026-11-08。本文用于新任务恢复长期共识；实现现状以源码和当前工作树为准，具体历史见 `开发记录.md`。建议与已确认决定分开记录，行为变化完成后同步更新。

## 产品与技术

中文离线叙事探索游戏，以雪夜旅馆、不断绕回的林路、线索调查和人物说法之间的矛盾展开。采用 TypeScript、Vite、原生 DOM 与 Tauri 2；无运行时服务端、远程素材或云存档。先验证网页前端，再按交付需要导出 Windows NSIS，不引入 Unity/Godot。

已发布的首轮试玩工程版本为 `0.1.0`。当前处于第二轮开发阶段（文档旧称“游戏 2.0”），软件版本统一为 `0.2.0`：package.json、package-lock、Tauri 与 Cargo 已同步；0.2.0 交付包于 2026-11-09 重建，未做 GitHub 发布。不要根据本文假定当前改动已提交或上传，开始工作时检查 Git。

## 玩家反馈与 2.0 目标

首轮反馈：重复循环较多、伏笔作用不明确、故事平淡且奇异感不足、体验不同结局需要重开。2.0 已获授权扩展场景和剧情，补充可重玩的存档能力，并用环境画面帮助玩家掌握空间。

设计目标：异常能够被观察或检验，线索影响追问和理解，人物说法与实际证据可以矛盾；减少无变化的重复操作；保持新场景与现有场景的连接。

## 已确认并实现的方向

- **旅馆外观**：一直不进入时，旅馆逐渐衰老、呈现年代变化；树林等周围环境保持连续。进入后的室内与先前外观构成矛盾；多次观察后可连续赶路减少点击。
- **隔壁半杯水**：先观察再提供喝水选择。房间表达“没有直接看见有人”，不能据此宣告从未有人住过或无人承认住过。
- **第一夜厨房**：恢复原设计里的野猪和制作香肠情节。早餐颜色/入口味道更像鹿肉，玩家可按实际所见所尝追问。
- **旧宴会厅**：新增场景通过一楼走廊双开门与厨房侧门连通，夜间关闭、白天探索；杯印、椅脚痕迹和片段话语提供线索。
- **地下室对话**：身份未明的残缺话语，不直接揭示人物身份。前台说法不是唯一结论。
- **存档与回溯**：每次选择后自动保存；三个手动档；当前旅程关键节点回溯；读取或回溯前归档当前旅程；历史归档供回看。保留旧版兼容、坏档拒绝、保存失败与其他窗口更新提示。
- **场景美术**：随包 28 张本地 WebP（原 31 张；保留原 12 张，2026-10-08 新增 19 张；2026-10-29 由 PNG 转为 WebP 后约 8.5MB；2026-11-09 移出 3 张无源码引用素材后约 7.3MB），低饱和全彩，云杉林、雪、灰石和旧木，中世纪城堡内饰参考。新增夜间门前近景、有人前台、两幅画像与登记簿/合影/早餐特写，室外昼夜、第一夜暗长廊及邻房、厨房人物与清晨、宴会厅杯印拖痕、肉墙和水下图。前台人物按剧情在场条件显示，线索特写仅在对应调查节点显示；新舞台用 H 隐藏文字观察，旧版放大入口目前未保留。
- **场景交互（2026-10-29 重做，取代 10-13 至 10-15 的标记/胶囊/避让方案）**：用户试玩后认为旧交互“反人类”。现为点击式冒险的做法：画中物件按真实位置设可点范围（`scenePresentation.ts` 的 anchor + area，百分比坐标），悬停时物件被暖光照亮并显示动作，单动作一次点击执行，多动作弹出就近小菜单；画外去处为画面左右边缘箭头；交谈话题与决定在旁白读完后列为文字选项（数字键可选）。旁白无框浮现在热区较少的一侧，点击空白/空格翻页。画面固定 3:2 画框、CSS 百分比定位，不再用 JS 测量与观察器。触屏轻点先出菜单再执行，物件缓慢呼吸发光。开场路线（森林、门前、遗迹、井边、前台）已按实图标定坐标；2026-11-03 用户确认满意后，进一步逐图校准客房、昼夜长廊和邻房、一楼走廊、昼夜厨房、宴会厅及地下室的点击范围。声音及未绘出的水道洞口保留文字入口，相关集中验收见 11-03 场景交互全面推广任务。
- **现有结局与谜题**：离开旅馆外林路、溺亡、退房、成为前台四个结局。衣柜是 20 根绳、40 个可移动端点的环形绳阵，完成条件为零交叉；井绳等局部解谜仍由代码绘制。

## 待评估事项（不是已承诺实施）

- **多窗口交错保存**：2026-10-15只读检查用内存存储复现比对与写入之间的竞态；已有保护仅能拒绝检测到的串行更新，两个窗口同一瞬间写入仍可能静默覆盖。后续需设计同源写入独占与异步保存反馈，验收交错写、锁等待的新进度及失败重试。现阶段同一进度使用单窗口，不把它列为已修复功能。

- 进一步细化部分室内昼夜、晨间门前近景及喝水后水位等静态物件状态；本轮已修主要室外昼夜和第一夜邻房灯光，但尚未为全部节点制作动态变体。

- 正式 0.2.0 发布的内容范围、验证与发布材料需在发布任务中确定（产品阶段旧称“游戏 2.0”）。
