# 开发记录

## 第 01 步 · 标题与开场选择 · 2026-09-21

### 本轮目的

把官方示例替换为用户能亲自点击的开场，验证“读一段文字 → 做选择 → 得到不同反馈”。按小步骤推进，之后再加游戏规则。

### 改动

- 暂用“雪夜旅馆”作为页面标题，加入本地 SVG 旅馆剪影与深色阅读布局。
- 提供标题页、开始按钮、返回标题、开场两条选项和各自的第一段叙述。
- 两条路线停在明确的试玩边界，可以回到开场体验另一条路线；不是正式剧情结局。
- 剧情文字放到 src/story/opening.ts，与界面显示代码分开；场景名称和跳转目标由 TypeScript 校验。
- 支持小屏幕、键盘焦点和系统的减少动画偏好。
- 原示例保存在 checkpoints/step-01-before.zip。原设计图未改动。

### 本轮范围

没有加入物品、日夜变化、融合、存档或隐藏结局。文字改编自原图，仍以用户的设计为准；下一轮先讨论试玩感受，再扩展正式场景切换与状态系统。

### 验证

- `npm.cmd run build` 通过：TypeScript 检查与 Vite 构建成功。
- 浏览器实际点击通过：标题 → 开场 → 靠近旅馆 → 回到开场 → 继续赶路 → 返回标题。
- Tab 可将焦点移到开始按钮，焦点轮廓清晰；场景切换后焦点落在新标题。
- 已查看宽屏标题与窄屏开场截图，文字和按钮没有被遮挡。
- 原始示例备份已生成（5,456 字节）。本轮未重新构建桌面程序或制作安装包，桌面预览仍通过 `npm.cmd run tauri dev` 启动。

## 第 02 步 · 探索与随身物品 · 2026-09-21

### 本轮目的

沿用用户认可的文字、按钮和页面切换效果，让选项开始影响后续剧情，并接上村庄探索和物品查看。

### 改动

- 第三次赶路发现村庄遗迹，第十次赶路触发“一直向前”结局；中间路程使用不同反馈。
- 遗迹提供夜间搜寻与休息到清晨的分支，清晨可调查画像和门牌。1682 年的线索以画像呈现，门牌信息记为文字线索。
- 加入戒指、画像、银钥匙和随身物品页；已知线索只在实际调查后显示。
- 戒指拾取一次，投井后从物品中移除，跨日后才出现银钥匙。画像和钥匙重复调查不会重复入包。
- 分别记录“持有戒指”“艾米莉看见过戒指”“读过戒指刻字”；进入旅馆后主动查看戒指，才在灯下读出刻字。
- 返回标题保留本次进度，可以继续探索；重新开始前给出提示。物品页返回原场景，不增加赶路次数或推进时间。
- 把剧情、物品、游戏状态、选择规则和画面显示拆开，方便之后修改文字或背景。
- 修改前备份：checkpoints/step-02-before.zip（10,128 字节，包含 src、index.html、README.md 和 package.json）。

### 本轮边界与暂定处理

- 主线在进入旅馆、与艾米莉第一次对话后显示试玩边界，可继续查看随身物品。登记簿、旅馆内部、住宿与融合值尚未接入。

- 仅保存当前运行期间的进度，刷新页面或关闭窗口会清空。没有写入正式存档。
- 正文为原设计的改编稿，后续可随用户的背景与文案调整继续修改。原设计图未修改。

## 第 03 步 · 入住与第一夜 · 2026-09-21

### 本轮目的

按原设计图和优化展示页，接上前台登记、客房第一夜、走廊调查与次日回访，让登记簿线索第一次和第二次露面。

### 改动

- 前台可以办理入住、主动查看登记簿和肖像画，也可以暂时返回旅馆外。登记簿线索始终可通过选项找到，不依赖随机事件。

- 办理入住后得到客房钥匙，可上楼；如果清晨抵达，安顿到客房时进入当晚。
- 第一夜可躺下、调查走廊与隔壁虚掩的房门。调查结果会记为线索；回房后仍可睡到清晨。

- 前台小姐的身份先由玩家结合画像和登记簿推断，叙述没有在初次见面时直接替玩家揭示。

### 本轮边界

- 第一夜结束后仍可回访前台与室外；更深入的旅馆调查、旧账本、融合值和最终退房日期尚未接入。

- 时间只有雪夜和清晨两种画面状态；后续若加入多日循环，需要细化白天与夜晚切换。
- 仍只保留本次运行内的进度，刷新会重置。原设计图未改动。

## 第 04 步 · 早餐与一楼调查 · 2026-09-21

### 本轮目的

从第一夜后的前台接出早饭选择和一楼线索，并开始记录原优化方案中的融合程度。

### 改动

- 清晨在前台可回应早餐邀请；接受后能观察香肠、吃下或假装吃，亦可婉拒。结果会改变后续前台状态，早餐不会重复领取。
- 加入内部融合值 0–6。吃下早餐增加 1，假装吃和婉拒不增加；画面以“旅馆像已经坐过许多次的餐桌”等感受表达，不显示数值。
- 早餐结束后，前台暂时无人，可查看上层抽屉并取得旧账本一次；下层柜门仍锁着。旧账本记录婚庆准备的蛋糕、猪肉香肠和啤酒。
- 一楼走廊与厨房门口可以调查，再安全折返前台。登记簿、客房、旅馆外和先前线索仍可回访。
- 物品页加入旧账本；只在实际观察早餐或取得账本后，线索列表才增加对应内容。
- 天数大于一天时，导航显示具体第几天，避免遗迹先休息过夜后仍把第三天写成“次日”。
- 修改前备份：checkpoints/step-04-before.zip（22,948 字节）。

### 本轮边界

- 融合值目前只有吃早餐这一项可改变。安心睡去、地下室获救和高融合分支将在对应剧情接入时实现，再检查 0–6 阈值是否合适。
- 厨房门口和下层锁柜暂不继续深入，避免玩家进入尚未完成的地下室路线。关键线索仍可从登记簿和旧账本取得。
- 没有正式存档；关闭或刷新窗口会回到标题。原设计图未改动。

### 验证

- `npm.cmd test`：16 项剧情规则检查通过，新增覆盖早餐三种回应、融合值、旧账本一次性取得与一楼安全折返。
- `npm.cmd run build`：TypeScript 检查与 Vite 构建通过。
- 浏览器实际点击：开场 → 入住 → 第一夜 → 清晨前台 → 接受早餐 → 观察香肠 → 吃下 → 回前台 → 拾取旧账本。
- 查看了清晨前台和早餐结果页截图，按钮、正文与边界提示可读。

## 第 05 步 · 两把钥匙与地下室入口 · 2026-09-21

### 本轮目的

接上第二天白天的隔壁客房、前台锁柜和地下室入口，按设计图明确两把钥匙的用途。

### 改动

- 第一夜后可回访二楼隔壁房间；白天才会发现衣柜门虚掩，并从中取得古铜色钥匙。夜间调查仍只揭示房间空着和楼下的响动。
- 早餐结束、前台暂时无人时可查看下层锁柜。没有古铜色钥匙只能观察；有钥匙可打开，取得女士衣物下面的旧合影。已见过 1682 年画像时，合影与画像的关联才会在叙述和物品说明中出现。

- 物品页新增古铜色钥匙与旧合影，银白色钥匙的说明会在地下室门打开后更新。修正客房钥匙说明过早揭示前台小姐身份的问题。

### 本轮边界

- 融合值仍属内部状态，早餐和首次安心睡去各可增加 1。阈值效果与更晚的融合事件要随下一段剧情接入。

## 第 06 步 · 地下室深处与水下分支 · 2026-09-21

### 本轮目的

按设计图接上地下室水边之后的两条路：沿墙探查旅馆的异常，或跳入汇水的洞口面对溺水与获救分支。

### 改动

- 从水边可涉水到水流汇聚的圆形洞口。玩家能沿墙寻找另一条路，也能明确选择跳入洞口；跳之前始终可以退回。
- 沿墙会看到掺着木纹的石壁、食物形状的肉瘤、倒塌石柱和墙上龙头。石柱与旧村庄的联系只在掌握相应线索后明确呈现；调查发现记录在随身线索中。
- 带着地下室发现回前台，可以质问前台小姐。她会说出“那不是我们的房子”“以前不是它的”；后续婚礼与旅馆真相留待下一段对话。
- 跳入洞口后按“前台小姐是否曾见过戒指”分支。此前未见戒指则进入水下结局；曾见过则被一只手拉起，次日回到客房。这个条件与当前是否还持有戒指分别记录，已投井的戒指不会在对话中凭空出现。
- 获救后融合值增加 2，仍限制在 0–6；客房与前台文字随获救状态变化，前台可追问救援。死亡结局返回标题时提供新游戏入口。
- 修改前备份：checkpoints/step-06-before.zip（28,203 字节）。原设计图未改动。

### 本轮边界

- 前台关于村庄、婚礼和离开旅馆的完整对话仍未接入；这轮在她初次承认地下室异状后标明试玩边界。
- 进度只在当前运行期间保留；刷新或关闭窗口会重置。

### 验证

- `npm.cmd test`：24 项剧情规则检查通过，新增覆盖沿墙线索、前台承认、死亡结局、曾见戒指但已投井时的救援、救援跨日和融合值上限。
- `npm.cmd run build`：TypeScript 检查与 Vite 构建通过。
- 浏览器实际点击：地下室沿墙调查石柱和龙头 → 返回前台追问；另验证跳洞后死亡结局与返回标题新游戏。
- 浏览器再次从头走通“前台见戒指 → 投井 → 取银钥匙 → 跳洞 → 获救 → 次日回前台”的路线，确认没有写出不存在的戒指。
- 查看了墙上龙头、死亡结局及获救后客房的截图，文字与按钮可读。

### 改动

- 艾米莉承认地下室与旧屋有关后，可以继续追问婚礼、爱德华、她的记忆和旅馆来历。婚礼当夜的风雪与宾客留下来的经过，是进入旅馆真相的必经谈话。

## 第 08 步 · 前台结局与一次获救 · 2026-09-22

### 本轮目的

补齐原流程图中“坐到柜台后，回应新旅人”的高融合结局，并阻止反复跳入水洞刷取融合程度。保留退房路线原有的关键对话。

### 改动

- 融合值仍按暂定的 0–6 记录，5 起可以走向前台结局。早餐、第一次安心睡去和首次获救之后，玩家若已对旅馆产生足够亲近感，可以明知地下室异常仍主动多住一晚；这一次选择推进一天、增加 1 点融合，因而正常游玩能到 5。
- 高融合回到前台时，前台小姐暂时离开。玩家可绕到柜台后、坐下，面对进门的新旅人回答“……当然。”；也可以在坐下前退回大厅，继续调查或寻找退房办法。
- 地下室救援每局只发生一次。再次来到洞口会提示那只手未必再来；若仍跳下去，就进入溺水结局，不重复增加融合程度。
- 退房路线补回原图中的婚礼后“第二天呢”“为什么没走”、艾米莉对自身身份的疑问，以及她谈旅馆来历时的停顿。填写退房日期后，她会望着日期很久，再让开通往门口的路。
- 高融合后再回客房，文字会反映又住了一晚；前台无人场景也与柜台后的选择保持一致。
- 修改前备份：checkpoints/step-08-before.zip（40,855 字节）。原设计图未改动。

### 当前边界

- 四个结局都可到达；夜间厨房调查、证物组合对质和室外不同融合程度的更多反馈，仍可在后续剧情轮次细化。
