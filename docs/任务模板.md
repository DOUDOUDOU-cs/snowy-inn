# 开发任务模板

复杂功能在 `docs/tasks/YYYY-MM-DD-简短任务名.md` 建立一个文件。主 agent 维护，子 agent 通过交接返回进展；简单改字不必创建。只填写本轮所需信息。

```markdown
# 任务名称

状态：规划中 / 实施中 / 待审计 / 已完成 / 待输入
更新日期：YYYY-MM-DD

## 目标与依据
- 玩家要解决的问题：
- 用户已确认需求：
- 相关设计/源码/项目上下文：
- 本轮范围与暂不纳入的建议：

## 需求根源（持续返工、目标不清或跨领域任务填写）
- 原始困扰与需求为何产生：
- 事实/推断/未知及证据：
- 能减少重复工作的最小修正与代价：

## 验收标准
- [ ] 用可观察行为描述结果，包括触发条件与预期反馈。
- [ ] 所需分支、空间返回、存档兼容或布局检查。

## 分工与接口
| 子任务 | 负责角色 | 允许编辑文件 | 依赖/接口 | 交付 |
| --- | --- | --- | --- | --- |

共享文件负责人：
依赖顺序：

## 决策与假设
- 已确认：
- 可逆的实现假设与理由：
- 需要用户补充的关键问题（若有）：

## 进展与交接
- 已完成：
- 正在做：
- 下一步：
- 阻塞（若有）：

## 模块完成与测试交接
- 可独立验收的模块范围、接口与完成状态：
- 完成后交 test_engineer 的文件、标准、风险和未完成项：
- 现有同版本证据与无需重复的检查：

## 验证与审计
- 测试 agent：模块完成后集中执行，拒绝无关/重复/镜像实现测试。
- 实际命令/检查、日期与结果：
- 视觉证据/复现路线：
- 未验证项与原因：
- 审计问题及修复状态：

## 完成记录
- 最终改动：
- 同步更新的文档：
- 后续事项：
```
