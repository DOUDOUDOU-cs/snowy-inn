## 需求根源结论

- 事实：旧交互曾连续修补靠近展开、胶囊横展和旁白避让，最终因用户认为操作不自然而整体替换；多个阶段自动化通过但真实体验待验。证据为开发记录第 22–29 步和 10-29 任务。
- 高置信推断：交互模型未先以代表路线确认，导致围绕旧模型反复打补丁；源码/自动化证据与用户体验之间缺少明确交接，不能只以测试数评价体验或断言旧测试全部冗余。
- 事实：原前端、剧情、状态角色均自行要求测试/构建，主 agent 还负责验证和审计，存在重复执行诱因。
- 最小修正：保留 Claude 当前结构，交互模型变更先确认可试玩样板；实现角色完成模块后统一交专职测试，审计复用证据；不新增测试平台、动画框架或服务端。
- 边界：根源分析不是小修审批；模块按可独立验收行为定义，不等到整个游戏结束，也不拆成每次编辑一验。
