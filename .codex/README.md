# 项目 agent 配置与用法

## 文件位置与加载

- `.codex/config.toml`：项目的并发设置，最多三个子 agent 同时运行，不含主 agent。
- `.codex/agents/*.toml`：八个角色，每个包含 `name`、`description` 和 `developer_instructions`。本轮于 2026-11-03 按官方文档复核格式。
- `AGENTS.md`：主 agent 与子 agent 的项目约定和协作入口。
- `docs/项目上下文.md`：已确认方向、现有成果与需继续判断的事项。
- `docs/任务模板.md`：复杂任务的持久记录模板。

从 `game/` 启动新的 Codex 项目会话。项目须处于受信任状态，项目配置才能加载。配置变更不代表正在运行的会话已重新加载角色。父目录 `new_game/AGENTS.md` 仅用于指向实际仓库；该目录原先空的 `config.toml` 和 `agents/` 已移入仓库的 `.codex/`，避免维护两份配置。

未固定模型、推理强度、插件、MCP、机器绝对路径或审批模式，沿用客户端与主会话设置。按照当前官方文档，角色文件不能覆盖父会话的权限或建立独立只读沙箱；根源分析、规划和审计通过职责明确要求只读，已移除旧角色中的 `sandbox_mode`。配置不安装工具，也不保证子 agent 拥有图像生成能力。

## 角色分配

| 名称 | 角色 | 主要产出与边界 |
| --- | --- | --- |
| `root_cause_analyst` | 需求根源分析 | 解释需求为何产生，区分症状/根源/未知，给出减少返工的最小修正；只读 |
| `requirements_planner` | 需求合理性分析与拆分规划 | 玩家价值、范围、依赖与验收标准；只读，计划由主 agent 落盘 |
| `art_engineer` | 美术素材生成 | 场景简报、生成/编辑、图片检查、素材与生成记录；不改剧情或 UI |
| `frontend_engineer` | 前端样式与界面 | `index.html`、样式、UI 和场景映射；不自行重写游戏规则 |
| `narrative_gameplay_engineer` | 剧情与玩法 | 剧情、选项、物品、日记和谜题规则；新增字段先确定存档接口 |
| `state_desktop_engineer` | 状态、存档与桌面 | 本地规则、数据、迁移、回溯和 Tauri；对应本项目的后端职责 |
| `test_engineer` | 专职测试 | 模块开发和接口集成完成后集中选择、补充和执行必要验收；拒绝冗余测试 |
| `code_art_auditor` | 代码与美术审计 | 可复现问题、证据与验收建议；只读，修复另行分派 |

主 agent 负责集成与发布准备；实现角色静态自查并交接，专职测试 agent 在模块完成后集中验收，审计复用同版本证据独立判断缺陷。八个角色按需选用，不会每次全部启动，也不强制小修先做根源分析。

## 常规流程

1. 主 agent 读取相关上下文；持续返工、目标不清或跨领域需求先做根源分析，再按需拆分，在 `docs/tasks/` 记录任务。简单修改无需增加流程文件。
2. 明确状态/界面/素材接口及文件负责人。先做依赖项，再并行处理独立部分；同一文件同一时间一个编辑者。
3. 工程师完成一个可独立验收的模块，提交静态自查、改动和风险；不边写边跑测试。美术工具不可用时，主 agent 执行聊天生图并把最终素材路径交回。
4. 主 agent 确认模块与接口完成后，统一交 `test_engineer` 集中验收；主 agent 与审计复用证据。失败项退回原负责人，修复完成后只做失败/受影响项的定向复测。
5. 更新任务状态、长期决策和开发记录，向用户报告结果。没有执行的检查写为未验证。

子任务交接需要：任务路径、目标、依据、允许修改文件、依赖接口、验收标准、风险，以及“已完成/待测试/待完成/阻塞”的状态。不需要每轮重复全部项目历史。

## 拒绝冗余测试

- 模块指可独立验收的一组行为及必要接口，不是每次小编辑，也不是整个游戏。模块未完成时不运行测试、构建或反复做浏览器验收；现有实现的学习演示与新模块验收分别记录。
- 测试 agent 先映射验收标准和真实风险，再复用现有覆盖，选择最小充分批次；不新增镜像实现、只断言常量/样式字串或重复覆盖的测试，不追求测试数量。
- 纯配置/文档只检查 TOML、引用与规则一致性，不运行游戏套件、网页构建或 NSIS。全量套件、打包、扩围和重跑均需有具体风险或必需关卡依据。
- 审计与主 agent 不重复执行测试 agent 的同版本批次。证据足够即停止，未验证项明确记录；专职测试不是在原有自验之外再叠加一层。

## 使用示例

新会话中可直接说：

> 按项目 agent 分工完成宴会厅的调查扩展：先理解原始困扰与空间路线，再完成剧情、场景图及前端模块，模块完成后集中交测试 agent 验收，最后按需审计；以项目文件记录决策与进展。

单项也可说：

> 请使用 code_art_auditor 检查本轮 diff 中图片和剧情是否一致，提供问题与证据。

若当前客户端未提供按名称调用自定义角色的接口，主 agent 读取对应 TOML 的职责作为子任务指示，用已提供的子 agent 工具分派；应明确这是按职责分派，不能声称该客户端已加载自定义角色。若没有子 agent 工具，主 agent 按相同职责顺序执行并报告限制。

## 维护与来源

修改角色后，检查 TOML 语法、角色名唯一、引用文件存在，并重新打开 `game/` 会话验证加载。只更新一份仓库配置，不复制个人全局设置。新增工具按实际客户端能力处理，不能在配置中杜撰生图开关。
