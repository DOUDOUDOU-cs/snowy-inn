# 项目 agent 配置与用法

## 文件位置与加载

- `.codex/config.toml`：项目的并发设置，最多三个子 agent 同时运行，不含主 agent。
- `.codex/agents/*.toml`：六个角色，每个包含 `name`、`description` 和 `developer_instructions`。当前格式按 Codex CLI 0.160.0 与 2026-10-08 官方文档核对。
- `AGENTS.md`：主 agent 与子 agent 的项目约定和协作入口。
- `docs/项目上下文.md`：已确认方向、现有成果与需继续判断的事项。
- `docs/任务模板.md`：复杂任务的持久记录模板。

从 `game/` 启动新的 Codex 项目会话。项目须处于受信任状态，项目配置才能加载。配置变更不代表正在运行的会话已重新加载角色。父目录 `new_game/AGENTS.md` 仅用于指向实际仓库；该目录原先空的 `config.toml` 和 `agents/` 已移入仓库的 `.codex/`，避免维护两份配置。

未固定模型、推理强度、插件、MCP、机器绝对路径或审批模式，沿用客户端与主会话设置。规划和审计角色配置了只读默认值，其他角色继承权限；运行时权限和组织策略可能覆盖默认值，职责约定仍要求规划和审计不写项目。配置只定义职责，不安装工具，也不保证子 agent 拥有图像生成能力。

## 角色分配

| 名称 | 角色 | 主要产出与边界 |
| --- | --- | --- |
| `requirements_planner` | 需求合理性分析与拆分规划 | 玩家价值、范围、依赖与验收标准；只读，计划由主 agent 落盘 |
| `art_engineer` | 美术素材生成 | 场景简报、生成/编辑、图片检查、素材与生成记录；不改剧情或 UI |
| `frontend_engineer` | 前端样式与界面 | `index.html`、样式、UI 和场景映射；不自行重写游戏规则 |
| `narrative_gameplay_engineer` | 剧情与玩法 | 剧情、选项、物品、日记和谜题规则；新增字段先确定存档接口 |
| `state_desktop_engineer` | 状态、存档与桌面 | 本地规则、数据、迁移、回溯和 Tauri；对应本项目的后端职责 |
| `code_art_auditor` | 代码与美术审计 | 可复现问题、证据与验收建议；只读，修复另行分派 |

主 agent 负责集成与发布准备，因此不再单设项目经理、测试或发布角色。专业工程师验证自己的交付，审计角色独立复查。六个角色不会每次全部启动。

## 常规流程

1. 主 agent 读取相关上下文，必要时让规划角色拆分；在 `docs/tasks/` 记录本轮任务。简单修改无需增加流程文件。
2. 明确状态/界面/素材接口及文件负责人。先做依赖项，再并行处理独立部分；同一文件同一时间一个编辑者。
3. 工程师提交改动和证据；美术工具不可用时，主 agent 执行聊天生图并把最终素材路径交回。
4. 主 agent 集成并按具体风险验证，交审计角色复查。审计指出的问题分派原负责人修复。
5. 更新任务状态、长期决策和开发记录，向用户报告结果。没有执行的检查写为未验证。

子任务交接需要：任务路径、目标、依据、允许修改文件、依赖接口、验收标准，以及“已完成/待完成/阻塞”的状态。不需要每轮重复全部项目历史。

## 使用示例

新会话中可直接说：

> 按项目 agent 分工完成宴会厅的调查扩展：先分析需求和空间路线，再实现剧情、场景图及前端接入，最后审计；以项目文件记录决策与进展。

单项也可说：

> 请使用 code_art_auditor 检查本轮 diff 中图片和剧情是否一致，提供问题与证据。

若当前客户端未提供按名称调用自定义角色的接口，主 agent 读取对应 TOML 的职责作为子任务指示，用已提供的子 agent 工具分派；应明确这是按职责分派，不能声称该客户端已加载自定义角色。若没有子 agent 工具，主 agent 按相同职责顺序执行并报告限制。

## 维护与来源

修改角色后，检查 TOML 语法、角色名唯一、引用文件存在，并重新打开 `game/` 会话验证加载。只更新一份仓库配置，不复制个人全局设置。新增工具按实际客户端能力处理，不能在配置中杜撰生图开关。

2026-10-08 配置检查：七个 TOML 文件解析通过，六个角色名唯一且必填字段完整；本机 Codex CLI 0.160.0 的 `app-server --strict-config` 与 `config/read` 实际读取项目层，`agents.enabled = true`、并发上限为 3，项目层未被跳过；`debug prompt-input` 确认项目 AGENTS.md 内容进入指令。六个角色尚未逐个启动执行任务，后续首次分派时检查角色选择及工具可用性。为使仓库层生效，个人配置仅补充了 `game/` 的 trusted 项目登记。
